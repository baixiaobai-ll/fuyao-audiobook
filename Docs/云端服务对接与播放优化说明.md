# 云端服务对接与播放优化说明

本文记录与**自建 API（可部署在阿里云等）**的对接约定，以及客户端**边播边生成 / TTS 并发 / 预取**相关配置，便于后续继续完善服务端。

---

## 一、客户端配置入口

| 配置项 | 来源 | 说明 |
|--------|------|------|
| `DISCOVER_API_BASE_URL` | `Config.plist` 或环境变量 | API 根地址，**无末尾斜杠**，需 **HTTPS**（满足 ATS） |
| `maxConcurrentTasks` | `UserDefaults`，键名 `maxConcurrentTasks` | TTS 并发上限，默认 **24**，最大 **100**（与讯飞等接口上限对齐时可调大） |
| `streamPlaybackWhileGenerating` | `UserDefaults` | **边播边生成**，默认 **true**（勿长期为 false，否则易表现为「整章合成完才播」） |
| `chapterPrefetchProgressThreshold` | `UserDefaults`，键名 `chapterPrefetchProgressThreshold` | 下一章正文预取基准阈值 **0～1**，默认 **0.18**；实际触发点会由 `PlaybackGenerationPacing` 按当前段数与并发微调 |

首次安装若曾写入旧默认（如并发=3），可在设置页或调试时改 `UserDefaults`，或删 App 重装。

---

## 二、云端 API 约定（与 `DISCOVER_API_BASE_URL` 同源）

### 1. 发现页（可选）

- `GET /v1/discover/ranking`
- `GET /v1/discover/category?sort=...`

返回书籍列表 JSON（数组或 `{ "books": [...] }` / `{ "data": [...] }`），字段需含 `title`、`author`、`bookId`、`coverURL`/`cover` 等（与客户端 `DiscoverAPIClient` 解码逻辑一致）。

### 2. 播放分析索引（无正文上云）

- **GET** `/v1/playback/analysis?bookId=&chapterIndex=&textHash=`  
  - `textHash`：对 **`NovelTextAnalyzer.canonicalTextForPlayback(原始章文本)`** 的 UTF-8 字节做 **SHA256**，**64 位小写 hex**。  
  - 命中：**200** + `PlaybackAnalysisIndex` JSON（或包在 `{ "analysisIndex": ... }` / `{ "data": ... }`）。  
  - 未命中：**404** 或非 2xx 即可（客户端走本地 AI 分析）。

- **POST** `/v1/playback/analysis`  
  - Body：`{ "analysisIndex": { ... } }`  
  - 索引结构见工程内 `Sources/Bookshelf/PlaybackAnalysisIndex.swift`（**不含** `segments[].text`，仅有 UTF-8 偏移与类型/角色/场景等）。

服务端存储键建议：`(bookId, chapterIndex, textHash)`。

## 三、播放体验相关逻辑（已实现）

1. **边播边生成**：`Config.streamPlaybackWhileGenerating` 默认为 **true**；`BookChapterPlayback` 将 `stream` 传入 `AudioBookGenerator.generate`，首段就绪即开始播。
2. **多段 TTS 并发**：`AudioBookGenerator` 对分段 **并行** 调用 `TTSEngine.synthesize`，并发由 **`TTSConfig.maxConcurrentRequests`**（与 `Config.maxConcurrentTasks` 一致）限流。
3. **有序回调**：`OrderedPlaybackEmitter` 保证 `onItemReady` 仍按段序 0、1、2… 触发，避免乱序进播放器。
4. **预取下一章正文**：`ChapterPrefetchCoordinator` 在播放进度达到 **动态阈值**（基于 `chapterPrefetchProgressThreshold`、当前列表段数、`maxConcurrentTasks`）时，后台拉取下一章文本写入 `ChapterContentManager`。
5. **节拍粗算**：`PlaybackGenerationPacing`（`Sources/Player/PlaybackGenerationPacing.swift`）提供启发式方法，用于判断「生成能否跟上收听」、建议预取比例等（可结合线上数据调参）。

## 四、你（服务端）待办清单（下次继续）

1. 在阿里云上部署 HTTPS API，实现上述路径与 JSON 契约。  
2. 在 App 的 `Config.plist` 写入 `DISCOVER_API_BASE_URL`。  
3. 按需调大客户端 `maxConcurrentTasks`（不超过 100），观察稳定性与耗电。  
4. 若仍偶发卡顿，可适当提前 `chapterPrefetchProgressThreshold` 或继续提高并发/优化段长。

更细的字段级说明可直接对照 Swift 中 `PlaybackAnalysisIndex`、`DiscoverAPIClient`、`PlaybackAnalysisCloudClient` 源码。
