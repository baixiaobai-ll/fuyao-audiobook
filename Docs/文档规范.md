# 文档规范

这份规范用于统一“扶摇”项目中的文档职责、命名和归档方式。

## 1. 文档分层

### 根目录

只保留高频入口型文档：

- `README.md`
  项目总览、运行方式、关键入口
- `快速开始.md`
  新人或回到项目时的最短启动路径
- `CHANGELOG.md`
  面向版本演进的持续更新记录

### `Docs/`

只保留当前仍然有效的正式文档：

- 架构设计
- 开发指南
- 部署与优化
- API / 配置说明
- 某个仍在使用的专项方案说明

### `Docs/Archive/`

归档以下文档：

- 阶段性过程记录
- 一次性交付说明
- 某天的工作备忘
- 已过期的启动说明
- 已完成任务清单
- 临时问题修复记录

归档文档默认不删除，先集中沉淀，后续再按需要二次清理。

## 2. 命名规则

### 当前有效文档

使用能表达用途的稳定名称，例如：

- `架构设计.md`
- `开发指南.md`
- `API密钥配置.md`

避免使用这类临时性命名作为长期正式文档：

- `README_FIRST.txt`
- `开始开发.txt`
- `明天如何继续.md`
- `项目已创建.md`

### 归档文档

保留原始文件名，放入带时间语义的归档目录中，方便回溯上下文。

推荐格式：

- `Docs/Archive/2026-03-legacy/`
- `Docs/Archive/2026-04-release-notes/`

## 3. 内容要求

### README

必须回答这 4 个问题：

1. 这是什么项目
2. 现在怎么运行
3. 核心目录在哪里
4. 先看哪些文档

### 快速开始

必须控制在“短路径”内，优先写：

1. 配置什么
2. 用什么方式启动
3. 启动后先测什么

不要把长期设计、历史背景、冗长示例都塞进去。

### 开发指南

面向持续开发，重点写：

- 工程结构
- 开发环境
- 调试方式
- 常见工作流

### 归档文档

不再承担当前入口职责，只保留历史信息。

## 4. 维护规则

新增文档前先判断：

1. 它是当前长期有效吗
2. 它是入口文档还是专题文档
3. 它是否只是一次性工作记录

判断标准：

- 长期有效：放根目录或 `Docs/`
- 阶段性记录：直接放 `Docs/Archive/`

以后继续整理时，优先遵循“不删历史，先归档；不留多入口，避免重复”。
