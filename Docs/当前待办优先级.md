# 当前待办优先级

这份文档用于统一记录“扶摇”当前阶段的执行重点。

阅读方式：

- 如果目标是今晚先做出一个可用初版，先看“今晚最小闭环”
- 如果目标是后续继续扩展能力，再看“后续路线图”
- 如果要给不同 worktree 分配任务，就以这份文档为准

## 今晚最小闭环

今晚的目标不是把所有能力都做完，而是做出一个可安装、可演示、可继续迭代的最小版本。

### 今晚必须完成

#### 1. 主链路稳定

用户至少能够顺畅完成以下路径：

- 打开 App
- 在发现页找书
- 进入书籍详情页
- 点击章节开始分析
- 完成 TTS 合成
- 成功开始播放

这是今晚最核心的交付标准。

#### 2. Kimi 分析链路可用

当前文本分析模型已经切到 Kimi K2。

今晚只要求做到：

- 分析阶段不频繁超时
- 能稳定返回分段和角色信息
- 出现异常时有本地降级，不让整章直接失败

今晚不要求做到：

- 提示词完全最优
- 参数完全最优
- 角色识别达到最终理想效果

#### 3. Kimi 分析结果驱动 TTS 语气

这是今晚需要补上的差异化能力之一。

目标：

- 使用 Kimi 分析出的 `emotion / sceneType / intensity`
- 映射到讯飞 TTS 当前可控的语气和情绪参数
- 先做有限档位，不追求一次覆盖全部风格

建议今晚先覆盖：

- 平静
- 紧张
- 悲伤
- 激动
- 温柔

只要这条映射基本生效，就已经具备初版价值。

#### 4. 播放页状态保留

目标：

- 退出 App 后再次进入，播放页不为空
- 能恢复上一次的书籍、章节和最近播放上下文
- 避免出现“明明在听，回来后播放页什么都没有”的体验

这是影响用户感知非常明显的一项，优先级高。

#### 5. 发现页基础体验

今晚发现页只要求做到“可用且不太慢”。

目标：

- 搜索可用
- 首屏加载不要太慢
- 列表和详情打开不要明显卡住
- 基础样式过关

今晚不要求直接把完整云端缓存体系全部搭完。

#### 6. 关键页面视觉收口

今晚要收顺的页面：

- 书架页
- 书籍详情页
- 播放页
- 发现页
- 我的页

目标不是做成最终精修版，而是：

- 页面层级清楚
- 空态和状态切换自然
- 没有明显粗糙和割裂感

#### 7. 激活码 + 每天 10 章限制

这是今晚唯一需要补的最小权限/成本控制闭环。

目标：

- 支持输入激活码
- 激活成功后绑定当前设备
- 每个设备每天最多可读 10 章
- 超额时给出明确提示

今晚只做最小版，不做：

- 短信注册
- 完整账号体系
- 订阅支付
- 多端同步

## 今晚明确不做

为了确保初版今晚能收口，这些事情暂时不做：

- 短信验证码注册
- 完整订阅体系
- Web search 书源兜底
- 1000 用户并发扩容实现
- 完整云端缓存平台
- 大范围工程重构

这些不是不做，而是不能挤进今晚的最小闭环。

## 后续路线图

以下内容是“今晚初版之后”的方向。

### P1：短期接着做

#### 1. 继续打磨 Kimi 提示词与参数

方向包括：

- 调整温度、top_p
- 优化系统提示词
- 优化 context 边界
- 提高角色识别与情绪识别质量

#### 2. 深挖讯飞 TTS 参数能力

方向包括：

- 更细的情绪档位
- 场景与语气联动
- 不同角色的表达力度差异
- 旁白与对白的语音风格分离

#### 3. 发现页更完整的缓存体系

方向包括：

- 热门榜单缓存
- 书籍详情缓存
- 章节目录缓存
- 云端缓存与本地缓存配合

#### 4. 播放页和最近播放体验继续打磨

方向包括：

- 最近播放列表
- 更稳定的恢复策略
- 更完整的进度展示
- 多书切换体验

### P2：产品化能力

#### 5. 激活码系统升级

后续可以继续加：

- 激活码后台管理
- 激活码批量生成
- 激活码状态与失效控制
- 设备解绑与重绑策略

#### 6. 订阅与额度系统

在激活码最小版稳定后，再考虑：

- 订阅支付
- 非订阅用户额度
- 订阅权益放开
- 调用成本统计

#### 7. 账号体系

后续如需要再做：

- 手机号注册
- 验证码登录
- 账号找回
- 多端同步

### P3：稳定性和规模化

#### 8. 多书源与 Web search 兜底

目标：

- 不再强依赖单一笔趣阁接口
- 书源失效时仍可搜索和拉章节
- 为后续更稳的发现页能力打基础

#### 9. 并发容量评估

目标：

- 评估 1000 用户量级时模型和接口成本
- 明确缓存、限流、队列、预生成等能力需求
- 为后续后端升级做预算

## 当前建议的执行顺序

如果按今天晚上的节奏来，推荐顺序如下：

1. Player 主链路稳定
2. Kimi 到 TTS 语气映射
3. 激活码 + 每天 10 章最小闭环
4. 播放页状态保留
5. 发现页基础提速和样式
6. 我的页样式收口

## 备注

判断今晚是否可以收工，不看“完成了多少愿望清单”，只看以下问题是否能回答“是”：

- 用户能顺畅找书并听书吗？
- Kimi 分析和 TTS 基本稳定吗？
- 播放页回来后还有状态吗？
- 发现页可用吗？
- 成本控制是否至少有激活码和每日 10 章限制？

如果这些都满足，就算今晚的最小闭环达成。
