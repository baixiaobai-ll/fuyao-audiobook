# 开发指南

这份文档描述“扶摇”当前实际可用的开发方式，而不是项目早期的理想流程。

## 项目定位

“扶摇”当前是一个以 iOS 为主的 SwiftUI 应用。

开发时请区分两层：

- `App/`
  iOS 界面层与交互流程
- `Sources/`
  共享业务层与核心能力

当前推荐工作流：

- 用 Xcode 运行和调试完整 iOS App
- 用 `swift build` 检查共享层 `Sources/` 是否可编译

## 当前目录结构

```text
App/                         # SwiftUI 界面层
  FuyaoApp.swift             # App 入口
  ContentView.swift          # Tab 容器
  BookshelfView.swift        # 书架
  BookSearchView.swift       # 发现页
  BookDetailView.swift       # 书籍详情 / 章节入口
  NowPlayingView.swift       # 播放页
  ProfileView.swift          # 我的

Sources/                     # 共享业务层
  Bookshelf/                 # 书籍模型、书源、章节缓存、发现页数据
  TextAnalysis/              # 文本分析
  TTSEngine/                 # TTS 合成
  AudioMixer/                # 混音
  Player/                    # 播放器与播放模型
  AudioBookGenerator.swift   # 生成链路协调器
  Config.swift               # 配置与密钥读取
  UserProfileStore.swift     # 用户资料

Docs/                        # 当前有效文档
Docs/Archive/                # 历史文档归档
project.yml                  # iOS 工程定义
Package.swift                # 共享库构建描述
```

## 环境要求

### 必需

- macOS
- Xcode 15+
- iOS 16.0+ 目标环境

### 建议

- 真机与模拟器都保留一套测试路径
- API 密钥通过 `Config.plist` 或 Scheme 环境变量管理

## 工程与构建方式

### 1. Xcode

这是主开发入口。

适合做的事：

- 运行完整 App
- 调试界面交互
- 验证搜索、播放、章节切换
- 检查真机和模拟器行为

### 2. `swift build`

这是共享层健康检查入口。

适合做的事：

- 检查 `Sources/` 是否还能编译
- 发现跨平台兼容或基础语法问题

不适合做的事：

- 代替完整 iOS App 运行
- 判断 `App/` 界面层是否能在 iOS 上正常工作

## 配置方式

项目配置读取优先级：

1. 环境变量
2. Keychain
3. `Config.plist`

关键配置见：

- [API密钥配置.md](../Docs/API密钥配置.md)
- [Config.swift](../Sources/Config.swift)

常见配置项：

- `AI_API_KEY`
- `TTS_API_KEY`
- `AI_PROVIDER`
- `TTS_PROVIDER`
- `AZURE_REGION`
- `DISCOVER_API_BASE_URL`

当前约定：

- `AI_PROVIDER` 默认使用 `kimi`（Moonshot Kimi K2.6，国内端点 `api.moonshot.cn`）
- 备选：`AI_PROVIDER=qwen`（阿里 dashscope 通义千问，仅作为兜底，K2.6 不可用时再切）

## 常用开发路径

### 1. 跑起 App

推荐顺序：

1. 配好 `Config.plist`
2. 在 Xcode 打开工程
3. 选择模拟器或真机
4. 运行后先检查四个主页面：
   - 书架
   - 发现
   - 播放
   - 我的

### 2. 验证发现页

重点关注：

- 分类是否加载成功
- 搜索是否优先返回真实线上结果
- 搜索失败时是否回退到缓存结果
- 点击书籍能否正常进入详情页

关键文件：

- [BookSearchView.swift](../App/BookSearchView.swift)
- [BookSourceEngine.swift](../Sources/Bookshelf/BookSourceEngine.swift)
- [DiscoverAPIClient.swift](../Sources/Bookshelf/DiscoverAPIClient.swift)

### 3. 验证章节播放

重点关注：

- 章节正文是否拉取成功
- 长章节是否会分批生成
- 首段是否能尽快起播
- 后续分段是否持续追加到播放器

关键文件：

- [BookDetailView.swift](../App/BookDetailView.swift)
- [BookChapterPlayback.swift](../App/BookChapterPlayback.swift)
- [AudioBookGenerator.swift](../Sources/AudioBookGenerator.swift)
- [AudioBookPlayer.swift](../Sources/Player/AudioBookPlayer.swift)

### 4. 验证本地 TXT 导入

重点关注：

- 文件能否正常导入
- 章节切分是否合理
- 导入后正文是否被缓存
- 能否直接进入播放链路

关键文件：

- [BookshelfView.swift](../App/BookshelfView.swift)
- [ChapterContentManager.swift](../Sources/Bookshelf/ChapterContentManager.swift)

## 推荐调试方式

### Xcode 调试

优先使用：

- 断点
- 控制台日志
- 模拟器 + 真机对照验证

适合重点观察的场景：

- 搜索连续提交时结果是否串台
- 章节切换时播放状态是否正确
- 进度保存后重新进入是否恢复正常

### 命令行检查

共享层编译检查：

```bash
swift build
```

这条命令应该保持可通过，用来尽早发现共享层回归。

## 修改代码时的建议

### 改 `App/`

优先考虑：

- 用户路径是否更顺
- 页面状态是否更清晰
- 是否破坏现有入口和导航

### 改 `Sources/`

优先考虑：

- 是否影响多个页面
- 是否影响缓存与播放状态
- 是否影响跨模块协作

### 改文档

遵循：

- 入口文档放根目录
- 正式文档放 `Docs/`
- 历史材料放 `Docs/Archive/`

具体规范见：

- [文档规范.md](../Docs/文档规范.md)

## 建议的开发顺序

如果你回到项目准备继续推进，推荐顺序是：

1. 在 Xcode 跑一遍 App
2. 验证“发现”页搜索
3. 验证长章节播放
4. 再处理具体缺陷或功能迭代

这样最接近真实用户体验，也最容易发现真正重要的问题。
